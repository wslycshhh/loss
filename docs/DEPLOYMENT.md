# Windows / 企业内网部署

## 有 Node 的构建机

从指定仓库克隆，在仓库根执行：

```sh
git clone https://github.com/wslycshhh/loss.git
cd loss
npm ci
npm test
npm run build
```

Vite 是构建期开发依赖；[官方构建说明](https://vite.dev/guide/build.html)介绍静态产物和相对路径。`vite.config.mjs` 使用相对 base。

把整个 `dist` 目录交给既有 IIS、Nginx 或其他内网静态服务器。保留 `assets` 相对路径，并为 HTML 使用及时更新的缓存策略。无需部署 Node 后端、数据库或外部服务。

## 没有 Node 或无法访问 npm 的终端

在有网、已获准的构建机完成安装、测试与构建，将构建产物复制到目标终端或内网静态服务。

`dist/offline.html` 为单文件版本：样式/脚本/公开数据均内嵌；CSP 使用内嵌脚本 SHA-256，并禁止运行时连接。可尝试用现代 Edge / Chrome 打开，目标公司的本地 HTML、CSP、文件选择和下载策略需要实际验收。浏览器策略禁止文件模式时，使用已批准的内网静态服务，不修改策略绕过。

Firefox 等现代浏览器也可作为目标浏览器，需在公司的实际策略下确认本地 HTML、文件导入和报告下载。公司电脑不必直接拉取 GitHub 或安装 npm 依赖：在获准构建机打包，再通过公司的批准渠道传递产物即可。

## 本机预览地址连接失败

`127.0.0.1:4175` 只指当前浏览器所在电脑，需同一台电脑上有预览服务运行。它不是公网或永久托管地址。预览进程退出后，Firefox 会提示连接失败。

已安装依赖并完成构建的 Windows 源码目录可双击 `Start-Loss.cmd`；窗口保持打开时服务持续运行，关闭窗口或 Ctrl+C 停止。也可直接运行：

```sh
npm run preview -- --port 4175 --strictPort --open /offline.html
```

使用离线单文件不依赖这个服务。请先确认进程与端口状态，不因连接失败而修改公司代理、防火墙或浏览器安全策略。

依赖安装可使用组织已批准的 npm 镜像；不要在源码中写入私有 registry 凭据。

## 内部规则与报告

私有文件留在公共仓库及静态站点根目录之外。通过网页的“导入本地规则包”选择；仅在浏览器内存中计算。刷新或“清除导入”后移除。未自动保存数据，因此刷新前请按需导出报告。

SI JSON 包含所选规则来源、修订、核查日期、状态、项目输入、查询频点、参考面和限值。已导入规则另含源文件 SHA-256。若使用内部规则，导出的报告也是内部材料，不能放回公共仓库或公开站点。

仅比较实测点时的通过状态不代表频点之间、全温老化或整条链路通过。无实测时只输出规格预算。公共规则选择与企业内部资料可分开部署，构建时不需要私有附件。
